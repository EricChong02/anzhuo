# 让 AI 协助安装远窗

把下面这句话发给你电脑上的编程助手。安装助手可以和远窗之后使用的模型不同。

> 请把 https://github.com/EricChong02/anzhuo.git 安装到我这台电脑。拉取后先读仓库里的 AGENTS.md 和 docs/AI协助安装.md。先看看这台电脑已有的环境，再把需要我决定的问题一次问清楚。按我的回答完成安装和测试，告诉我怎么打开远窗、哪些功能已经能用。

## 安装前，向使用者确认什么

如果这是首次安装，先确认当前电脑是否就是长期运行远窗的主机。可以自己查到的资料，例如当前操作系统、处理器架构、`uv` 和已安装的命令，先在本机核对。把剩下会影响方案的问题合在一条消息里。参考下面几类，按情况挑选，用户已交代的内容直接沿用。

| 主题 | 可以这样问 | 回答影响什么 |
|---|---|---|
| 平时用哪些 AI | 你平时用 Claude Code、Codex、接 DeepSeek 的 Claude Code，还是其他工具？想只接一种，还是有主用和备用？哪些已经能正常使用？ | 要配置和验收哪些引擎。多引擎时再问是否需要按任务设默认模型、是否允许切换备选。 |
| 是否使用 CyberScope | 你是否已在自己的 CyberScope 环境里备课？想在远窗里试课、提交反馈或改课吗？ | 默认安装远程工作功能。确认要用试课后，再核对本机 CyberScope 的预览地址和课件目录，配置可选模块。 |
| 哪些设备要用 | 远窗要装在哪台电脑上？你通常会从哪台手机、平板或其他电脑打开？最需要的是浏览器访问、主屏入口、通知还是文件分享？ | 安装方式和功能受运行主机影响。访问设备通常只需确认系统和浏览器。确实影响兼容时再问具体型号或系统版本。 |
| 怎么接入，装好先做什么 | 你想先在本机用，还是需要出门也能打开？已有域名、反代或 Tailscale 等入口吗？装好后第一件想用它完成的事是什么？ | 决定先做本机验证，还是继续配置远程入口。用用户自己的第一个任务当验收场景。 |

只询问与安装有关的信息。账号和密钥由使用者通过本机登录界面或凭据存储配置，聊天里只需确认是否已经登录或配好。

## 根据回答完成安装

1. **简短复述方案。** 说清远窗运行在哪台电脑、会接哪些引擎、从哪里访问、准备开启哪些可选功能。把用户的愿望与仓库当前支持情况对齐。macOS 和 Windows 的差异见 [安装与首次运行](安装与首次运行.md)。普通网页访问和手机推送要分别判断。只有主机在运行并保持网络可达，其他设备才能使用它。
2. **先把最常用的路径跑通。** 按 [安装与首次运行](安装与首次运行.md) 安装依赖、配置网页登录并启动服务。Claude 按需登录 SDK 自带的 Claude Code。Codex 用主机上可用的 Codex，按该引擎的方式登录，再在远窗里选 GPT。DeepSeek 按 [配置参考](配置参考.md#deepseek-引擎codex-选型号) 配置，当前依赖 macOS 钥匙串。`anzhuo check` 会显示 Claude 的登录状态。只用其他引擎时，以该引擎在远窗里完成一次任务为准。
3. **把日常习惯落实到配置。** 优先用用户本机的 `config.toml` 或远窗设置配置常用工作目录、模型及备选、回复语言、通知等。接入外网按 [外网访问](外网访问.md) 选择 HTTPS 方案。使用 CyberScope 的用户按 [CyberScope 试课](CyberScope试课.md) 开启模块。安装前已有配置时，先读取并保留既有设置，只调整本次需要的项。
4. **需要额外能力时，再决定改哪里。** 配置能满足的直接配置。能独立接入的能力优先放本地扩展。确实需要改源码时，说明具体缺口、计划改动和以后如何跟上游合并，再在用户自己的分支上按授权实现和验证。本地适配和向上游提交是两件事。
5. **按实际使用路径验收。** 用临时目录在远窗里给选定引擎发一句简单任务，核对能收到回复。用户要在别处用，再核对目标设备能登录并完成一次任务。启用了试课时，用测试课验证预览和提交反馈。交付时写清入口、已开的功能、实际测过的设备和引擎，以及仍需要在其他设备或网络上验证的项目。

如果用户只想先看界面，可以先跑仓库的本机演示，等确定要装哪些功能再接入真实账号。
