# 外网访问：在任何设备上打开远窗

远窗的网页服务**只听电脑本机的 `127.0.0.1:8765`**，不对局域网、不对外网开放——这是故意的。要从别的设备打开，需要你自己再搭一条“从那些设备到这个本机端口”的通路。这一篇讲三种做法。

> **先说清楚：这条通路要你自己准备。远窗不提供任何中转服务，作者自己的服务器也不对外开放使用。**

## 整体思路

```
家里的 Mac ──（只有它需要能连上 Claude / GPT）
   │  主动连出去（SSH 反向隧道）
   ▼
你自己的服务器（nginx + HTTPS，只转发）
   ▲
   │  打开一个网址、登录
手机 · iPad · 任意一台电脑   ← 这些设备不需要代理，也不需要装任何软件
```

这样分工的好处：**AI 在家里那台 Mac 上干活，只有它需要连上 Claude / GPT**（如果它需要代理，配在它身上就行）；你在外面用的任何设备，只要能打开你自己服务器的网址就行。所以请**选一台你的设备不用代理就能访问的服务器**。

三种方案怎么选：

| 你想要 | 推荐 |
|---|---|
| 访问设备**不用装任何东西、不用代理**；能收手机推送通知；电脑不开任何端口 | [方案 A：自己的服务器 + SSH 反向隧道](#方案-a自己的服务器--ssh-反向隧道推荐作者在用的)（需要一台服务器和一个域名） |
| 不想买服务器，只给自己的几台设备用 | [方案 B：Tailscale](#方案-btailscale-serve)（每台设备都要装 Tailscale 并保持连接） |
| 已经有托管在 Cloudflare 的域名，不想买服务器 | [方案 C：Cloudflare Tunnel](#方案-ccloudflare-tunnel)（访问是否顺畅取决于你的网络环境） |
| 电脑上已经跑着一个带反向代理的自托管控制台/面板，远窗作为它的一个子应用出现，不新增隧道与域名 | [方案 D：挂在已有自托管面板的子路径下](#方案-d挂在已有自托管面板的子路径下)（要求远窗支持子路径，配 `web_prefix`） |

> **关于验证程度，说实话**：方案 A 是作者本人长期使用的做法，仓库里的脚本就是为它写的，经过实际使用；方案 B、C 是业界通用做法，原理上和远窗兼容（远窗只要求“一个 HTTPS 地址转到 `127.0.0.1:8765`”），但作者没有逐项实测，细节请以对应产品的最新文档为准。

不管哪种方案，**三条共同要求**：

1. **必须是 HTTPS。** 登录 Cookie 在 `https://` 下才带 `Secure` 标记；手机通知（Web Push）和“添加到主屏幕当 App”也要求 HTTPS。
2. **把配置里的 `web_base` 改成你最终的 HTTPS 地址**（如 `web_base = "https://anzhuo.example.com"`），然后重启远窗。`web_base` 决定通知里链接的写法和 Cookie 的 `Secure` 属性。
3. **反向代理要把真实来源 IP 追加到 `X-Forwarded-For` 的最后**。远窗的“登录防暴力”（同一来源连错 5 次锁 15 分钟）只认这个头的**最后一段**，前面的可以被伪造。nginx、Cloudflare、Tailscale Serve 默认都会处理。

## 方案 A：自己的服务器 + SSH 反向隧道（推荐，作者在用的）

结构：

```
任何设备 ──HTTPS──▶ 你的服务器 nginx（域名 + 证书）──▶ 服务器 127.0.0.1:18765
                                                        ▲
                                  SSH 反向隧道（电脑主动连出去，launchd 保活）
                                                        │
                                          电脑 127.0.0.1:8765（远窗）
```

**电脑不开放任何端口**——隧道是电脑主动连出去的；服务器上只有 nginx 和一条隧道，**没有远窗的任何密钥和数据**，登录和业务都在电脑上。电脑睡着或断网时，nginx 会返回一个“电脑那边没连上”的页面，15 秒自动重试。

**需要**：一台有公网 IP 的服务器（Debian / Ubuntu 系，装了 nginx 和 certbot）、一个域名、能用 SSH 密钥登录服务器。

### C1. 让电脑能免密登录服务器

在 `~/.ssh/config` 里给服务器起个别名（下面用 `my-server`）：

```
Host my-server
    HostName 203.0.113.10        # 你的服务器 IP
    User root                    # 或有 sudo 的账号；enable_web.sh 要改 nginx 和证书
    IdentityFile ~/.ssh/id_ed25519
```

验证：`ssh my-server echo ok` 不问密码、输出 `ok`。

### C2. 解析域名、准备 80 端口

1. 在域名的 DNS 里加一条 A 记录：`anzhuo.example.com` → 服务器 IP；
2. 在服务器上建好申请证书要用的目录，并给这个域名建一个**只含 80 端口**的 nginx 站点（`enable_web.sh` 会在这个文件后面追加 443 的那一段）：

   ```bash
   sudo mkdir -p /var/www/letsencrypt-anzhuo
   sudo tee /etc/nginx/sites-available/anzhuo.example.com >/dev/null <<'EOF'
   server {
       listen 80;
       listen [::]:80;
       server_name anzhuo.example.com;
       location /.well-known/acme-challenge/ { root /var/www/letsencrypt-anzhuo; }
       location / { return 301 https://$host$request_uri; }
   }
   EOF
   sudo ln -sf /etc/nginx/sites-available/anzhuo.example.com /etc/nginx/sites-enabled/
   sudo nginx -t && sudo systemctl reload nginx
   ```

### C3. 签证书、配 HTTPS（脚本一步做完）

在电脑上，仓库根目录运行：

```bash
scripts/enable_web.sh my-server anzhuo.example.com
```

它会通过 SSH 在服务器上：用 certbot 签 Let's Encrypt 证书（`certbot` 会自动续期）→ 往那个 nginx 站点追加 443 段（`proxy_pass` 到 `127.0.0.1:18765`、关掉缓冲以支持实时推送、请求体最大 450MB、`X-Robots-Tag: noindex`、电脑不在线时的提示页）→ 测试并重载 nginx。它**只加这一个站点**，不碰别的。可选第三个参数改服务器端口（默认 18765）。

### C4. 改配置、装隧道

```toml
# ~/.config/anzhuo/config.toml
web_base = "https://anzhuo.example.com"
```

```bash
scripts/install_launchd.sh                 # 重启远窗，让新 web_base 生效
scripts/install_tunnel.sh my-server        # 装隧道：本机 8765 → 服务器 127.0.0.1:18765
```

隧道是 launchd 常驻的（开机自启、断了自动重连）。重复运行 `install_tunnel.sh` 等于重启隧道。

### C5. 验证

```bash
curl -s https://anzhuo.example.com/_x/health
```

隧道通的时候返回成功；电脑那头远窗没连上时 nginx 会给 502 和那个提示页。然后在手机浏览器里打开 `https://anzhuo.example.com`，用 `anzhuo passwd` 设的账号密码登录。

### 一个已经踩过的坑：残留的旧隧道

网络断过一下时，服务器上常还留着上一条隧道的 sshd 占着 18765，新隧道连不上，网页一直转圈。`scripts/tunnel.sh` 在每次连接前会先用 SSH 登上去**清掉占着这个端口的旧 sshd**（日志里会写“清掉服务器上占着 … 的旧隧道”）。注意这一步需要服务器账号能执行 `ss` 和 `kill`；如果你把隧道账号收紧成“只能转发”，这一步会失败（被忽略），只是少了自动清理。

### 想把隧道账号收紧一点（可选）

如果不想让隧道账号有完整权限，可以在服务器上给它单独的 SSH 密钥，并在 `authorized_keys` 里限制它只能做端口转发，例如：

```
restrict,port-forwarding,permitlisten="127.0.0.1:18765" ssh-ed25519 AAAA… 你的备注
```

（`enable_web.sh` 仍需要一个有 sudo 的账号跑一次；日常的隧道用受限账号即可。参数写法以 `man sshd` 的 `authorized_keys` 一节为准。）

## 方案 B：Tailscale Serve

把电脑和手机放进同一个 [Tailscale](https://tailscale.com) 虚拟局域网，再用 Tailscale Serve 把本机端口变成**只有你自己的设备能打开**的 HTTPS 地址。

1. 电脑和手机都装 Tailscale 并登录同一个账号；
2. 在 Tailscale 管理后台开启 **MagicDNS** 和 **HTTPS Certificates**；
3. 电脑上运行（具体写法以 `tailscale serve --help` 为准）：
   ```bash
   tailscale serve --bg 8765
   ```
   它会告诉你一个类似 `https://你的电脑名.xxxx.ts.net` 的地址；
4. 配置里写 `web_base = "https://你的电脑名.xxxx.ts.net"`，重启远窗；
5. 手机上打开 Tailscale（要保持连接），浏览器访问这个地址。

优点：不用服务器、不暴露在公网。缺点：手机必须开着 Tailscale；没有“远窗掉线提醒”这套服务器端的脚本。

## 方案 C：Cloudflare Tunnel

如果你的域名托管在 Cloudflare，可以用 `cloudflared` 建一条命名隧道，把 `https://anzhuo.你的域名` 转到 `http://127.0.0.1:8765`。

1. 安装 `cloudflared`（`brew install cloudflared`），按官方文档创建命名隧道并绑定域名；
2. 隧道的 ingress 写成 `service: http://127.0.0.1:8765`；
3. 配置里写 `web_base = "https://anzhuo.你的域名"`，重启远窗。

建议再加一层 **Cloudflare Access**（只放行你的邮箱），和远窗自己的密码形成两道门。

## 方案 D：挂在已有自托管面板的子路径下

你的电脑上如果已经跑着一个自带反向代理的自托管控制台 / 面板（电脑控制台、Home Assistant、各类 Dashboard……），远窗可以**作为它的一个子应用**挂在其域名的子路径下，不新增隧道、证书和域名，HTTPS 与入口都由面板统一提供：

```text
手机 / 电脑 ──HTTPS──▶ panel.example.com
                        ├─ /            → 面板自己
                        └─ /yuanchuang/ → 反向代理 → 127.0.0.1:8765（远窗）
```

前提是面板把 `/yuanchuang/*` **原样透传**给远窗（不剥前缀），并追加 `X-Forwarded-For`；SSE（`/yuanchuang/_x/api/events`）要直通不缓冲。面板侧这样配好后：

1. 配置里写 `web_prefix = "/yuanchuang"`，重启远窗。远窗会把自己的所有路由（页面、`_x` 下的接口和资源、文件下载）都挂到 `/yuanchuang/...` 下，页面里的引用也会自动带上前缀；
2. `web_base` 填**面板的 origin**（协议 + 域名 + 端口，**不含路径**），如 `web_base = "https://panel.example.com"`。写接口的同源校验比较的是浏览器发来的 `Origin`（只有 origin、没有路径），填面板的 origin 正好对上；它也决定通知里链接的写法和 Cookie 的 `Secure` 属性；
3. 验证：浏览器打开 `https://panel.example.com/yuanchuang/` 应该能看到远窗登录页，登录后正常使用即可。

登录、密码、危险命令审批等安全模型不变，全部留在远窗自己身上；Cookie 的 `path` 仍是 `/`（同一个自托管面板内无风险）。

## 在设备上怎么用

1. 在任何设备的浏览器里打开你的 HTTPS 地址，用账号密码登录（这台设备 30 天内免登录）；
2. **加到主屏幕**（iPhone / iPad：Safari 的分享菜单 → 添加到主屏幕），之后像 App 一样全屏打开；
3. 从主屏幕图标打开后，侧栏有“**开启手机通知**”，点一下授权。要求 iOS / iPadOS 16.4 以上；
4. “⋯”里的“登录的设备”能看到所有登录着的设备，不认识的随时退出。

## 掉线提醒（可选）

电脑睡着、断网或关机时，手机上就收不到任何东西——但你**不知道**它掉线了。方案 A 可以在服务器上加一个“看守”：每分钟探一次远窗的健康接口，连续 3 分钟连不上就给手机推一条“远窗连不上了”，恢复后再推一条。

1. 配置里写 `watch_host = "my-server"`（和 `~/.ssh/config` 里的别名一致）。之后每当手机通知的订阅变化，远窗会把订阅文件同步到服务器的 `/opt/anzhuo-watch/push.json`；
2. 在服务器上：
   ```bash
   sudo mkdir -p /opt/anzhuo-watch && cd /opt/anzhuo-watch
   sudo python3 -m venv venv && sudo venv/bin/pip install pywebpush
   ```
3. 把 `scripts/server_watch.py` 复制到 `/opt/anzhuo-watch/`；
4. 把推送签名私钥放到服务器（权限 600）——在电脑上取出它：
   ```bash
   security find-generic-password -s anzhuo.webpush -a vapid -w
   ```
   把输出的那一串存成服务器上的 `/opt/anzhuo-watch/vapid.txt`（先在远窗里点过一次“开启手机通知”，这个密钥才会生成）；
5. 加 cron（每分钟一次；`ANZHUO_WATCH_SUB` 填你的联系方式，VAPID 协议要求有）：
   ```
   * * * * * ANZHUO_WATCH_SUB=mailto:you@example.com /opt/anzhuo-watch/venv/bin/python /opt/anzhuo-watch/server_watch.py
   ```

## 电脑睡着了怎么办

远窗运行时会在**插着电**时阻止 Mac 睡眠（`caffeinate -s`）；合盖或用电池时照常睡。想让它整夜在线，就插着电、别合盖，或者在“系统设置 → 电池 / 锁定屏幕”里调整。睡着时手机上连不上是正常的，醒来后隧道会自动重连。
