# 案头 · 详细设计方案（复刻用）

> 版本：2026-10-26。按项目当前实际运行的代码整理，给想自己复刻一套的人看。
> 原名“小E”，代码仓库名 `remote-claude`。文中域名、服务器、路径都换成了示例值。

---

## 0. 一句话说明

**人不在电脑前，也能用手机、平板或学校电脑，指挥家里那台 Mac 上的 Claude Code 和 Codex 干活：看它做到哪一步，要拍板时几十秒内拍完，做完收到推送和报告。**

它不是一个新的 AI 助手，而是给本机 Claude Code / Codex 套的一层**遥控外壳**：

- 干活的就是 Claude Code / Codex 本身。项目里的 `CLAUDE.md`、Skill、Hook 护栏、子代理、MCP 原样生效。
- 用的是本机登录的订阅（Claude 订阅、ChatGPT 会员带的 Codex），不走 API 按量计费。
- 外壳负责：收发消息、分派到哪个对话、并行与排队、中途插话、危险操作确认、过程实时可视化、推送、交文件、额度显示。

### 0.1 适合谁

- 主要靠 Claude Code / Codex 干活，经常离开电脑，又不想让活停下来。
- 有一台常开的 Mac（Linux 也行，要改启动方式和钥匙串）。
- 有一台带公网 IP 的小云服务器，或者愿意用 Cloudflare Tunnel、Tailscale 代替。

### 0.2 刻意不做的

- 不做多用户。整套系统只认一个人。
- 不做通用聊天助手的记忆和人设。闲聊只用一个小模型顺手答。
- 不自己实现 AI 智能体循环，全部交给官方 SDK 和 CLI。
- 不在服务器上跑任何 AI，服务器只做转发和掉线看守。

## 1. 用起来是什么样

| 场景 | 做法 |
|---|---|
| 课间派活 | 手机上说“在课程根新开：按剧本做第 2 课第 3 节”，附一张截图。自动开一个新对话，选文件夹和模型，开干。 |
| 路上拍板 | 手机弹通知“等你回答：封面用哪张？”。点进去看并排样稿，点“选 B”，或者打一句话。它接着干。 |
| 危险操作 | 它要 `git push` 或删文件时停下来，手机弹“等你确认”，点允许或不允许。20 分钟不点就当不允许。 |
| 沙发上深干 | iPad 打开网页：左边对话列表，右边完整对话。能实时看它在想什么、跑了什么命令，回复边写边出。可以中途插话。 |
| 收文件 | 让它“把整理好的表格发我”，网页里出现下载条，钉钉里收到文件消息。 |
| 掉线提醒 | Mac 睡着或断网超过 3 分钟，手机收到“连不上了”；恢复后收到“恢复了”。 |

## 2. 总体架构

```
 iPhone / iPad / 学校电脑                       手机钉钉
  （网页，可加到主屏幕当 App）                    │
          │ HTTPS                                 │ 钉钉服务器（Stream 长连接，Mac 主动连出去）
          ▼                                       │
 ┌─────────────── 云服务器（只转发）────────────┐   │
 │ nginx：域名 + 证书 → 127.0.0.1:18765          │   │
 │ Mac 连不上时返回“暂时连不上”页（15 秒自动重试） │   │
 │ cron 每分钟：看守脚本探活 → Web Push 掉线通知    │   │
 └───────────────▲─────────────────────────────┘   │
                 │ SSH 反向隧道（Mac 主动连出，launchd 保活）
                 │                                  │
 ┌───────────────┴──────────── 家里的 Mac ─────────┴──────────────┐
 │ 案头主进程（Python asyncio，launchd 开机自启、崩了自动拉起）         │
 │                                                                  │
 │  钉钉收发 ── 指令解析 ── 分派员（Haiku：接着哪个 / 新开 / 直接答）     │
 │       │                         │                                │
 │  网页服务（aiohttp :8765）── 对话登记表（sessions.json）              │
 │   · 登录 / 设备    · 实时推送 SSE                                  │
 │   · 对话 API      · Web Push                                      │
 │   · 预览转发（可选）                                               │
 │                                 │                                │
 │                    Runner：每个对话一个工作协程，最多并行 3 个        │
 │                     ├─ Claude 引擎：Claude Agent SDK（ClaudeSDKClient）│
 │                     │    · 危险命令 PreToolUse 钩子 → 等你确认        │
 │                     │    · 自带 MCP 工具：send_images / send_files   │
 │                     └─ Codex 引擎：codex app-server（stdio JSON-RPC）│
 │                          · 命令审批回调 → 同一套危险确认              │
 │                                                                  │
 │  辅助：翻译（DeepSeek → Haiku 兜底）、额度查询、存储清理、空闲重启      │
 └──────────────────────────────────────────────────────────────────┘
```

**设计要点：**

1. **Mac 不开放任何端口。** 钉钉走官方 Stream 长连接，网页走 SSH 反向隧道，都是 Mac 主动连出去。
2. **云服务器无状态、无密钥（推送私钥除外）。** 登录、鉴权、业务全在 Mac 上。服务器被攻破，也只能看到加密流量的终点。
3. **对话存在 Claude Code / Codex 自己的目录里。** 桌面端、命令行、手机三边都能接着聊同一个对话。案头只记“编号 ↔ 会话 ID ↔ 文件夹”的对应关系。
4. **前端是单个 HTML 文件，每次请求都重新读。** 只改界面不用重启进程，刷新就生效。

## 3. 技术选型

| 部分 | 选择 | 为什么 |
|---|---|---|
| 语言 | Python 3.13 + asyncio | Claude Agent SDK 官方有 Python 版；单进程异步，够用且好维护 |
| 包管理 | uv | 快，锁文件可复现 |
| Claude 引擎 | `claude-agent-sdk`（ClaudeSDKClient） | 官方 SDK：流式输入（能插话）、钩子、进程内 MCP 工具、恢复会话、思考摘要、流式增量 |
| Codex 引擎 | ChatGPT 桌面版自带的 `codex app-server` | 常驻进程，JSON-RPC。支持中途插话（turn/steer）、停止、压缩、额度查询、命令审批回调 |
| 聊天入口 | 钉钉企业内部应用机器人（Stream 模式），`dingtalk-stream` | 不需要公网回调地址；卡片按钮回调走同一条长连接 |
| 网页 | aiohttp + 原生 HTML/JS 单文件 | 无构建步骤；SSE 实时推送 |
| 推送 | Web Push（`pywebpush` + VAPID） | iOS 16.4 起，加到主屏幕的网页能收系统通知，不用上架 App |
| 外网入口 | 云服务器 nginx + Let's Encrypt + SSH `-R` 隧道 | 自己可控；也可换 Cloudflare Tunnel |
| 密钥 | macOS 钥匙串（`security` 命令） | 不落盘、不进仓库 |
| 常驻 | launchd（`KeepAlive` + `RunAtLoad`） | 开机自启、崩溃重启 |
| 翻译 | DeepSeek（便宜快）→ Haiku 兜底 | 思考过程和部分回复是英文，手机上要看中文 |

依赖只有五个：`aiohttp`、`claude-agent-sdk`、`dingtalk-stream`、`pywebpush`、`requests`。

## 5. 核心数据结构

### 5.1 Session（一个对话）

```python
@dataclass
class Session:
    num: int                 # 编号 #N，用户看到的
    name: str                # 标题（第一句话生成，可改名）
    cwd: str                 # 主文件夹（它的 CLAUDE.md / 护栏生效）
    add_dirs: list[str]      # 额外可读写的文件夹
    engine: str = "claude"   # "claude" | "codex"，开了就不能换
    claude_id: str = ""      # Claude Code 会话 ID（resume 用）
    codex_id: str = ""       # Codex thread ID
    model: str | None        # opus / sonnet / haiku / None（默认）
    effort: str | None       # low / medium / high / xhigh / max
    status: str              # idle / running / queued / awaiting / error
    awaiting: str            # 在等用户回答的那句话
    seen: float              # 用户最后看过的时间，用于“新完成”未读标记
    last_summary: str        # 上一轮一问一答的摘要，给分派员看
    hidden: bool             # 收起（7 天没动自动收起）
    from_desktop: bool       # 接上的是桌面端开的对话
```

### 5.2 Turn（一轮活）

```python
@dataclass
class Turn:
    started: float; ended: float | None
    request: str             # 用户这一轮说的话
    model: str; effort: str
    steps: list[str]         # 人话步骤：“看 Downloads”“跑命令：列出大文件”
    timeline: list[dict]     # {t, kind: think|say|do|you, text, detail}，过程页和实时卡片用
    partial: str             # 正在写的回复（流式增量），SSE 推给网页
    final_text: str
    changed_files: list[str]; commands: list[str]
    images: list[str]; files: list[str]   # 交给用户的
    injected: int            # 中途插话次数
    confirm: dict | None     # 正在等确认的危险操作 {what, cmd, fut}
    accepting: bool          # 还能不能插话
    interrupted: bool; is_error: bool; error: str
    compacted: bool          # 这一轮里自动压缩过
    context_pct / usage ...  # 上下文用量
```

### 5.3 Job（排队的一条消息）

`text`、`images`（本地路径）、`files`、`finished`。“压缩”是一个特殊 Job：文本是常量 `COMPACT`（Claude 发 `/compact`，Codex 调 `thread/compact/start`）。

## 6. 关键流程

### 6.1 一句话进来之后

```
钉钉消息 / 网页发送
   │
   ├─ 网页里在某个对话页发的 → 直接交给这个对话（不用猜）
   │
   └─ 钉钉里发的：
        ├─ 只认白名单里的钉钉 ID 发来的单聊，其余忽略并记日志
        ├─ 只有图片：等 15 秒，和下一句话合成一件
        ├─ 固定说法（新开 / 列表 / 停 7 / 切到 7 / 模型 / 深度 / 压缩 / 额度 / 接着桌面……）→ 指令处理
        ├─ 引用了某条消息，或以“#7 ”开头 → 交给那个对话
        ├─ 像直接回复（“好的”“选B”“继续”“再大一点”）→ 交给当前对话，不调用分派员
        └─ 其余 → 分派员（Haiku，低档思考）输出 JSON：
              reply    → 闲聊 / 问用法，自己直接回答，附“交给 #N”按钮防判断错
              continue → 交给 target 对话
              new      → 新开，选文件夹；kind=dev 用 Opus，simple 用 Sonnet
              ask      → 拿不准，问用户“接着 #1 还是新开”
```

分派员的提示词要点：
- 主要看话题。
- 有对话正在做或刚做完时，倾向于 continue 它。
- 有对话在等回答、用户的话像在回答它时，continue 它。
- 拿不准时宁可 continue，不要 reply。

最近 30 分钟内直接回答过的闲聊也带给它，这样用户追问时能接上。

### 6.2 交给对话：排队、并行、插话

`Runner.submit(session, job)`：

1. 这个对话**正在做**且还能接话：
   - Claude：在同一个 `ClaudeSDKClient` 上再 `client.query(...)`。这是 SDK 的流式输入，和桌面端打字插话是同一机制。它手上这一步做完就会看到。
   - Codex：调 `turn/steer`（带 `expectedTurnId`），交给正在进行的这一轮。
   - 插话失败（刚好收尾）就退回排队，下一轮再做。
   - **正在压缩的那一轮不插话**，因为插进去会被压缩吞掉，改为排到压完之后。
2. 否则进这个对话的 `asyncio.Queue`，必要时启动它的工作协程。
3. 全局信号量限制最多 3 个对话同时干活，其余显示“排队中，前面的做完就做”。

Claude 插话还有一个细节：插的话没赶上这一轮时，SDK 会接着再开一轮。所以收到 `ResultMessage` 后要再等 4 秒，看还有没有新消息，把两轮读完再一起报告。

### 6.3 Claude 引擎

```python
options = ClaudeAgentOptions(
    cwd=s.cwd, add_dirs=s.add_dirs,
    model=s.model, effort=s.effort or default_effort,
    resume=s.claude_id,                                   # 接着上次的会话
    setting_sources=["user", "project", "local"],         # 和桌面端一样加载规则、Skill、Hook
    permission_mode="bypassPermissions",                  # 远程没法逐条点权限；危险的另外拦
    system_prompt={"type": "preset", "preset": "claude_code", "append": APPEND},
    mcp_servers={"xiaoe": 进程内 MCP（send_images / send_files）},
    max_buffer_size=64 * 1024 * 1024,                     # 默认 1MB，看一张大截图就超，整轮报错
    thinking={"type": "adaptive", "display": "summarized"},  # 要思考摘要，网页“工作过程”里显示
    include_partial_messages=True,                        # 回复边写边出
    hooks={"PreToolUse": [HookMatcher(matcher="Bash", hooks=[guard], timeout=CONFIRM_WAIT + 60)]},
)
```

消息流处理：

| 消息 | 处理 |
|---|---|
| `SystemMessage` init | 记实际模型；subtype 含 compact 时标记“自动压缩过” |
| `StreamEvent` | 只取主对话（`parent_tool_use_id is None`）的 `text_delta`，拼进 `turn.partial` |
| `AssistantMessage` | 思考块 → 时间线 think；文本 → say；工具调用 → 人话步骤 + 时间线 do；编辑类工具记改了的文件；Bash 记命令 |
| `ResultMessage` | 记 `session_id`（下次 resume）、错误、最终文本、用量 |

`APPEND` 是追加给每个对话的固定要求。原则是**只写要求、不写原因，不告诉它“你在被远程遥控”**：
- 用中文回复。
- 动手做了事就按五段汇报：要你做的、做了什么、改了哪些、自查结果、截图；空段不写。
- 要用户选方案时，先出截图，第一行写“要你定：”，选项写“A. …”，推荐写“推荐：A，理由”。
- 截图用 `send_images` 交，文件用 `send_files` 交。
- 改案头自己时只能用空闲重启脚本。

**进程内 MCP 工具**（`create_sdk_mcp_server`）：
- `send_images(paths)`：最多 6 张，校验存在且是图片。
- `send_files(paths)`：最多 10 个，每个不超过 300MB。

收下的路径记进 `turn.images` / `turn.files`。轮次结束时复制到 outbox，网页和钉钉照常发。

### 6.4 Codex 引擎（ChatGPT 自带的 Codex）

可执行文件在 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`，跑 `codex app-server`。协议是 stdio 上一行一条 JSON-RPC 2.0。

**启动与开会话：**
```
→ initialize {clientInfo}
→ (通知) initialized
→ thread/start {cwd, sandbox:"workspace-write", approvalPolicy:"untrusted",
                config:{sandbox_workspace_write:{network_access:true}},
                developerInstructions: 中文要求 + “交给你：路径”约定}
   或 thread/resume {threadId, ...同上}
```

**一轮：**
```
→ turn/start {threadId, input:[{type:"text"}, {type:"localImage", path}], effort}
← item/agentMessage/delta          回复增量 → turn.partial
← item/started / item/completed    agentMessage / reasoning / commandExecution / fileChange / webSearch → 时间线
← thread/tokenUsage/updated        上下文用量
← account/rateLimits/updated       额度
← turn/completed {turn:{status, error}}
插话：→ turn/steer {threadId, expectedTurnId, input}
停止：→ turn/interrupt {threadId, turnId}
压缩：→ thread/compact/start {threadId}   ← thread/compacted
额度：→ account/rateLimits/read
```

**Codex 反过来请求（服务器 → 客户端，带 id）：**
- `item/commandExecution/requestApproval`：先过危险识别。危险的走同一套确认，返回 `accept` 或 `decline`；不危险的直接 `accept`。
- 旧版 `execCommandApproval`：返回 `approved` 或 `denied`。
- 这类请求要**另开协程处理**，不能挡住读取循环，否则等用户点确认时所有事件都卡住。

**stderr 要单独开协程一直读掉**，否则管道写满，子进程会卡死。

**交文件：** Codex 没有进程内 MCP 工具，约定它在回复最后一行写“交给你：/绝对路径”。实际上它常常只写成 `[下载xx](/本机/路径)` 链接，所以两种都解析：链接指向存在的压缩包、PDF、Office、图片、视频，就当作交付；源码、说明文档的链接只算出处，不发。

**Codex 对话的历史：** Codex 的会话记录格式和 Claude 不同，网页历史直接用案头自己存的 `turns/*.json`，再加上内存里刚结束、还没落盘的那一轮。

### 6.5 危险操作确认

模式是“全部放行，只拦不可逆的”。远程逐条点权限没法干活，但删除、推送、改库要先过一道关。

**现在默认由 AI 审核员把这道关（`reviewer.py`，配置 `auto_review = true`）：**
- 命令命中下面的规则时，先交给另一个模型（Sonnet，低档思考，单轮、无工具、不落盘）判断。它看到的是：用户这次交代的事、最近几步、工作文件夹、规则认定的风险、命令原文。它只输出 `{"allow", "reason"}`。
- 放行原则：为完成用户交代的事而做的提交、推送、上线；删任务自己生成的临时文件和旧打包；丢弃自己刚做的改动。
- 拦下原则：和任务无关；删用户原始资料或真实数据；大范围删除、抹盘；强推 main；无关的 sudo；直接重启本系统；看起来在绕过护栏。拿不准时，能轻松撤销就放行，不能就拦下。
- 每次判断都写进过程时间线，报告底部列出“审核员替你判断：放行…；拦下…”。被拦下时，钩子的拒绝理由里带上审核员的原因，让干活的模型换做法。
- 审核员出错或超时（90 秒），才退回下面的“等你确认”。
- 每次约 4 秒；只在命中规则时调用，用量很小。
- 配套：给干活模型的固定要求里写明“做完并自查通过后，提交、推送、上线直接做，不要停下来问”，不然它会在回复里反复问“要不要提交”。

关掉审核员（`auto_review = false`）时，用的是下面原来的流程。

`guard.danger(cmd) -> 人话 | None` 的规则：
- **Git**：push、reset --hard、clean -f、branch -D、stash drop/clear、checkout --、restore（`--staged` 除外）
- **数据库**：DROP / DELETE FROM / TRUNCATE
- **系统**：sudo；launchctl bootout/unload/remove；launchctl kickstart -k（会打断其他对话）
- **磁盘**：diskutil erase/partition、mkfs、dd
- **批量操作**：chmod/chown -R；find -delete / -exec rm
- **远程**：ssh 上执行 rm、停服务、重启
- **rm / rmdir / trash**：目标不在临时目录（/tmp、/var/folders、$TMPDIR）就拦

确认流程（Claude 和 Codex 共用 `Runner.ask_confirm`）：

```
命令命中 → turn.confirm = {what, cmd, fut}
        → 同时：手机推送“等你确认：…” + 钉钉确认卡（允许 / 不允许）+ 网页对话里的确认卡
        → await fut，最长 20 分钟，超时当不允许
        → Claude：钩子返回 permissionDecision allow / deny（附原因，让它换个做法或停下问）
           Codex：返回 accept / decline
```

钉钉按钮回调里带 `allow:N` 或 `deny:N`，网页调 `/api/confirm/N`。先到的生效，另一边的卡片更新为“已允许”或“已拒绝”。

### 6.6 一轮结束：报告与推送

1. 解析最终文本：
   - 是否要用户拍板：以“要你定”开头且列了 A/B/C。是的话，钉钉另发一张选项按钮卡，点“选 B”就把“选 B：……”交回这个对话。
   - 是否在等回答，写进 `session.awaiting`。
2. 英文段落（连续 8 个以上英文单词，代码、命令、路径不算）先翻成中文，并注明译者。
3. 组装钉钉报告：
   - 正文是它写的五段；底部写编号、用时、改了几个文件、跑了几条命令、模型和深度。
   - 附上下文、5 小时、本周三行用量小表；上下文过七成、自动压缩过、额度过八成时加醒目提醒。
   - 超过 3500 字拆成几条发。
4. 截图、文件复制到 outbox，钉钉逐个发：图片消息；文件消息 20MB 以内，超了提示去网页下载。
5. 写 `turns/<id>.json`，过程页和 Codex 历史用。
6. Web Push，标题是对话名，正文一句话：
   - “做完了：<请求摘要>”
   - “等你回答：<它问的那句>”
   - “出错了，点开看原因”
7. 钉钉“安静模式”（默认开）：只发结果，开工、排队、插话这些过程消息只在网页里看。

### 6.7 压缩上下文

- 用户在网页点“压缩”或在钉钉发“压缩 7”，会入队一个 COMPACT Job。正在做时排到这一轮之后。
- 已经有压缩在排或在做，就不重复入队；对话忙的时候按钮置灰。
- 压缩期间发来的话进队列，不插进压缩那一轮。
- 压完报“59% → 12%”。

### 6.8 额度

- **Claude**：后台跑 `claude -p /usage`。这是本机 CLI 的内置命令，不调模型、不耗额度。解析出 5 小时和本周的百分比与重置时间，2 分钟内不重复查。
- **Codex**：开一个临时 app-server 连接调 `account/rateLimits/read`，取 primary（5 小时）和 secondary（本周）的 `usedPercent` 和 `resetsAt`。另有后台循环定期刷新。
- 网页侧栏底部显示两组进度条（Claude / GPT）。

### 6.9 读历史（网页显示完整对话）

Claude Code 的会话记录在 `~/.claude/projects/<路径转义>/<session_id>.jsonl`。SDK 自带的读取只从最近一次压缩点往后读，网页上就看不到早先的对话。案头的做法：

1. 用 SDK 内部的解析函数得到条目和当前链。
2. 从链首找压缩边界（compact_boundary）的 `logicalParentUuid`，顺着 `parentUuid` 把压缩前的那段接到前面。可能压缩过多次，要循环。
3. `type == "attachment"` 且 `attachment.type == "queued_command"` 的条目是**中途插的话**，也当作用户消息显示。
4. 用户发的图片在记录里是 base64，网页按需通过 `/api/uimg/<num>/<uuid>/<k>` 取出显示。

### 6.10 掉线检测

- Mac 端：提供无需登录的 `/_x/health`。
- 服务器端：cron 每分钟跑一次看守脚本，探 `127.0.0.1:18765/_x/health`（经隧道到 Mac）。
  - 连续 3 次失败就推送“连不上了”，恢复后推送“恢复了（断了约 N 分钟）”。
  - 推送订阅由 Mac 在订阅变化时 scp 过去；VAPID 私钥在服务器上也存一份，权限 600。
- nginx 遇到 502/504 返回一个“暂时连不上 Mac”的页面，带 15 秒自动刷新。
- 网页端：API 返回 502 或请求失败时，顶上挂一条“连不上 Mac”横幅，恢复后自动消失。
- Mac 端：主进程启动 `caffeinate -s -w <自己的 pid>`，接着电源时不睡眠。

### 6.11 改案头自己时怎么重启

在案头里让 Claude 改案头的代码时，干活的那个对话就跑在案头进程里，直接重启会把自己打断。所以：

- `scripts/restart_when_idle.py` 以后台方式启动（`start_new_session`，脱离当前进程）。每 5 秒读 `sessions.json`，连续 90 秒没有“在做”或“排队”的对话才让 launchd 重启，然后在钉钉里说一声。
- 危险规则里拦了 `launchctl kickstart -k`，`APPEND` 里也写明“只能用空闲重启脚本”。
- 只改 `static/app.html` 不用重启。

### 6.12 存储清理

每天跑一次：
- outbox 和 inbox 里超过 60 天的副本删掉，原件不动。
- 超过 90 天没动、且不在登记表里的 Claude 会话记录移到归档目录。

## 7. 网页端设计

### 7.1 页面结构（单页）

- **侧栏 / 首页列表**：
  - 标题加图标，下面一行概况：“下午好，<称呼> · 2 件在做 · 1 件等你”。
  - 对话按“需要你 / 在做 / 新完成 / 其他”分组。每行有引擎小标（C 赭石色、G 石墨色）、标题、状态和第几步。
  - 底部是额度条。
  - 开启通知、历史记录、登录的设备这几个入口也在侧栏里。
- **对话页**：
  - 顶栏：返回、标题和状态、上下文用量胶囊（点开有模型、深度、压缩按钮）、停下。
  - 正文：一来一回的对话。较早的长回复折起来；过程区可展开，思考翻成中文。
  - 实时卡片：显示做了多少秒、最近几步、边写边出的回复（带光标）。
  - 确认卡、排队提示、“要你定”的选项按钮、快捷回复（好的 / 就按你推荐的 / 先不做）。
- **新对话页**：
  - 一个输入框；下面一个“在哪做：自动”小按钮，点开选文件夹或“接着做某门课”。
  - 模型和深度选择器：自动 / Opus / Sonnet / Haiku / GPT，加低到最高五档深度。
- **输入框**：上面是文本区，下面一行是附件、模型胶囊、发送。高度最多占可视区的 30%。键盘弹起时用 `visualViewport` 把输入框托在键盘上。
- **手机布局**：一栏，先列表再进对话。历史只保留一层，返回一次就回到列表。
- **图片查看器**：双指缩放、双击放大、滚轮缩放；右上角清楚的“× 关闭”，点空白处也能关。

### 7.2 实时更新

- `EventSource('/_x/api/events?num=N')`：
  - 服务端每 0.4 秒比对列表和当前对话的签名，变了发 `s` 或 `t`，网页再拉对应接口。
  - 正在写的回复直接用 `p` 事件推全文。
  - 每 15 秒发一行注释保活（nginx 读超时是 120 秒）。
- 断开时退回轮询。
- 渲染时注意保持用户的阅读状态：
  - 正在选中文字时不重绘。
  - 记住展开状态和滚动位置。
  - 新回复到来时滚到这条回复的开头，而不是页面最底。

### 7.3 PWA 与推送

- `manifest.json`（name、图标 180 和 512、`display: standalone`）、`apple-touch-icon`、`apple-mobile-web-app-title`。
- Service Worker `/_x/sw.js`：
  - `push` 事件里 `showNotification(title, {body, tag, data:{num}})`。
  - `notificationclick`：先把要打开的对话编号写进 Cache，因为 iPhone 冷启动时不一定带上地址；再 `postMessage` 给已开着的页面，或者 `openWindow('/_x/?s=N')`。
- 网页启动时检查 Cache 里有没有待打开的编号，有就直接进那个对话。
- iOS 要求：必须先“添加到主屏幕”，从主屏幕打开后，由用户点击触发 `Notification.requestPermission()`。

### 7.4 网页 API 一览（都在 `/_x` 前缀下）

| 方法 路径 | 用途 |
|---|---|
| `GET /` | 单页 |
| `GET/POST /login` | 登录 |
| `GET /health` | 探活（免登录） |
| `GET /manifest.json`、`/icon.png`、`/icon-512.png`、`/sw.js` | PWA（免登录） |
| `GET /api/sessions` | 对话列表、文件夹、额度、在做的课 |
| `GET /api/thread/{num}` | 对话内容、实时状态、排队、用量 |
| `GET /api/events?num=` | SSE |
| `POST /api/send` | 发消息或新开对话（文字、图片 base64、文件），带文件夹、模型、深度 |
| `POST /api/settings/{num}` | 改这个对话的模型和深度 |
| `POST /api/confirm/{num}` | 危险操作允许或不允许 |
| `POST /api/compact/{num}`、`/api/stop/{num}` | 压缩、停下 |
| `GET /api/push/key`、`POST /api/push` | 推送公钥、订阅或退订 |

| `POST /api/feedback` | 可选：试课页反馈 |

所有写操作都校验同源（Origin / Referer）。

## 8. 安全设计

| 风险 | 做法 |
|---|---|
| 别人冒充你给机器人发消息 | 只认配置里 `allowed_user_ids` 的单聊，其余忽略并记日志 |
| 网页被撞库 | 账号加 PBKDF2-SHA256（30 万次）指纹，存钥匙串。同一 IP 错 5 次锁 15 分钟；所有来源一小时错 30 次全体锁一小时。来源 IP 只认 `X-Forwarded-For` 的最后一段（nginx 追加的那段），前面的可伪造 |
| 会话被盗 | Cookie 设 HttpOnly、Secure、SameSite=Lax，30 天有效。“登录的设备”列表可单个或全部下线；设备 ID 用会话 ID 的哈希前缀，不暴露原值 |
| CSRF | 写接口校验同源 |
| 密钥泄露 | 钉钉、DeepSeek、网页密码指纹、VAPID 私钥全在钥匙串；配置文件、仓库、日志里都没有 |
| 日志泄露隐私 | 日志只记消息类型和长度。原文只在本机 `recent.jsonl` 留最近 100 行 |
| 远程误操作 | 危险命令要确认（6.5）；Codex 另有沙箱，只能写工作目录 |
| 预览转发泄露数据（可选模块） | 白名单只放预览页、静态资源和少数只读接口；教师台、学生数据、WebSocket 一律不转 |
| 搜索引擎收录 | nginx 加 `X-Robots-Tag: noindex, nofollow` |
| 服务器被当代理 | 服务器只反代到隧道端口，不提供任何转发能力 |
| 手机丢了 | 网页里全部下线；钉钉里踢设备；Mac 上双击“停用”脚本 |

**提醒：** 对话以“跳过权限确认”运行。谁拿到你的钉钉账号或网页登录，谁就能指挥这台 Mac。危险操作确认是最后一道闸，不是第一道。

**合规：** 用自己的订阅在自己电脑上跑官方 SDK 和 CLI，属于个人本地使用。不要把这套东西做成多人共用的服务，否则违反订阅条款。动手前自己再看一遍 Anthropic 和 OpenAI 的最新条款。

## 10. 踩过的坑（复刻时直接避开）

| 坑 | 现象 | 解决 |
|---|---|---|
| SDK 默认 1MB 读缓冲 | Claude 看一张大截图，整轮报错 | `max_buffer_size=64MB` |
| 子进程 stderr 没人读 | Codex 跑一会儿卡死 | 单独开协程一直读 stderr |
| Codex 审批请求在读取循环里 await | 等用户确认时所有事件都停了 | 每个反向请求 `create_task` 单独处理 |
| SDK 只读压缩点之后的记录 | 压缩过的对话，网页上早先的内容全没了 | 顺着 `logicalParentUuid` 把前段接回 |
| 中途插的话在记录里是 attachment | 网页上插的话一直显示“发送中”的灰色 | 解析 `queued_command` 附件 |
| 压缩时插话 | 用户的话被压缩吞掉 | 压缩那一轮不插话，改为排队 |
| 新开对话时局部变量覆盖了用户选的模型 | 选了 GPT 却跑成 Opus | 用真实 Bridge 加假钉钉写端到端测试 |
| 前端热更新快于后端 | 新界面配旧后端，缺字段时默认值导致误标 | 字段缺失时不显示，不要猜默认值 |
| CSS 覆盖了 `hidden` 属性 | 按钮藏不掉，看起来像卡住 | 全局 `[hidden]{display:none!important}` |
| iPhone 冷启动点通知 | 打开的是首页，不是对应对话 | SW 先把编号写进 Cache，页面启动时读 |
| PWA 里打开图片没有返回键 | 用户被困在图片页 | 自己做图片查看器，不跳转 |
| SSE 被 nginx 缓冲或超时 | 实时更新一卡一卡的，或断开 | `proxy_buffering off` 加 `X-Accel-Buffering: no`，每 15 秒保活 |
| 翻译完成时重绘 | 正在看的思考框被刷新、滚动位置丢失 | 翻译中显示占位；选中文字时不重绘；记住展开和滚动状态 |
| 在案头里直接重启案头 | 自己被打断，别的对话也断了 | 空闲重启脚本，并把 kickstart -k 列为危险操作 |
| Codex 只写 Markdown 下载链接 | 手机上点不开，文件没交出来 | 解析链接；网页上本机路径链接只显示文字 |
| 后台进程访问“下载”文件夹 | TCC 弹窗没人点，永远卡住 | 先 5 秒探测，读不了直接报错并说明怎么授权 |
| 钉钉吊顶卡片 | 机器人单聊里用不了（只支持企业群） | 改用每次都重发到底部的“工作台”卡 |

## 11. 测试

- **单元测试**（pytest，47 项，约 4 秒）：危险命令识别、交文件解析、报告组装、指令解析、翻译判断、清理规则、历史读取（含压缩和插话）、网页登录与锁定、设备下线、预览白名单、反馈匹配等。
- **Bridge 集成测试**：假钉钉加假 Claude 走完整流程，包括分派、插话、排队、收起、卡片按钮、确认、压缩排队、“新开时保留所选模型”。
- **端到端**：
  - 起一个真实 Bridge，接假钉钉，用独立端口、临时数据目录和测试仓库。
  - 用 Playwright WebKit 模拟手机（402×874，3 倍像素）真点：Claude 流式、危险确认（允许和拒绝）、压缩排队、Codex 插话、停止、确认、交文件、压缩、额度、试课反馈、离线横幅、设备列表。
  - 测试脚本里危险命令的字面量用拼接生成，比如 `'pu' + 'sh'`，免得开发时自己的护栏先拦。
- **真机核对**：iOS 双指缩放、键盘高度、冷启动点通知、真实掉线 3 分钟的提醒，这几项必须在真 iPhone 上看。

## 12. 复刻路线与工作量

按“先能用、再好用”分期。工作量按“熟悉 Python、借助 Claude Code 写代码”估算。

| 期 | 内容 | 估计 |
|---|---|---|
| 1 | 钉钉收发文字和图片；固定说法；多对话并行加排队；Claude SDK 跑起来；五段报告；launchd 自启 | 1.5–2 天 |
| 2 | 分派员（Haiku）；中途插话；send_images / send_files；钉钉卡片（工作台、选项按钮）；翻译；额度 | 2 天 |
| 3 | 网页：登录、对话列表、对话页、发消息、过程页；隧道加 nginx 加证书 | 2–3 天 |
| 4 | SSE 实时推送、边写边出；PWA 加 Web Push；离线横幅加服务器看守；设备管理 | 2 天 |
| 5 | 危险确认（钩子 + 三端确认卡）；压缩；历史接回压缩前部分；存储清理；空闲重启 | 1.5 天 |
| 6 | Codex 引擎（app-server、插话、审批、交文件、额度、压缩） | 1.5–2 天 |
| 7 | 界面打磨：新对话页、模型选择、图片查看器、键盘适配、引擎标识、深色模式 | 2 天 |

合计约 2–3 周的业余时间。只做第 1–3 期，大约一周就有一个够用的版本。

**可以裁剪的：**
- 不用钉钉就只做网页加 Web Push。第 1、2 期的钉钉部分省掉，指令解析和分派员仍然有用。
- 换成飞书、Telegram、企业微信：只替换 `dingtalk.py` 和卡片格式，其余不动。
- 不用 GPT 就跳过第 6 期。
- 试课预览转发和“反馈这一屏”是作者自己的教学平台专用的，复刻时可以换成你自己项目的预览，或者直接不做。

## 13. 和现成方案的取舍

| 方案 | 优点 | 为什么没用 |
|---|---|---|
| cc-connect 等“聊天软件 ↔ 本地 Claude Code”桥 | 装上就能聊，支持平台多 | 一个聊天窗口一次只对着一个对话；没有并行派活、拍板卡、实时过程、危险确认 |
| Hermes Agent（Nous Research） | 多平台网关、记忆、定时任务、插件 | 干活的是它自己的智能体；用 Claude 订阅受限（官方文档：只有 Max 加额外额度可用），否则走 API 计费；要让 Claude Code 真正干活等于用插件重写本方案的核心 |
| claudecodeui 等网页版 Claude Code | 网页现成 | 没有手机推送、拍板、钉钉入口；要加的部分比现成的多 |
| Claude 官方的远程方案 | 官方维护 | 写这份文档时不能同时驱动 Codex，也接不进自己的预览和反馈流程 |

**结论：** 需求的核心是“并行派活 + 结果和拍板主动找到我 + 干活的就是带着项目规则的 Claude Code”。这三点现成方案都要大改，自己写一层薄外壳反而更省。
