# 远窗同网加速与自动回退

## 现在的方案

继续使用原桌面图标与 `https://xiaoe.ericlab.cn/_x/`，不把手机的全局 DNS 绑定到 Mac。

- **iPhone（iOS 26+，已确认用户为 iOS 27）**：通过一个 DNS 配置描述文件，仅在 WiFi 下将远窗域名交给 Mac 的加密 DNS。设置 `AllowFailover=true`，本地解析器不可达时允许系统回退到默认 DNS。蜂窝网络不启用这套配置；其它网站不交给 Mac 解析。
- **Mac 本机**：独立 HTTPS 网关运行在 443；在 `/etc/hosts` 中只把远窗域名指向 `127.0.0.1`，不用经过阿里云。这项 hosts 修改需系统授权，单独确认执行结果。
- **Mac 带出门 / 休眠**：不再让手机整网断 DNS。远窗域名通过系统回退恢复公网解析；切换时可能有短暂等待或连接缓存，不声称毫秒级无缝切换。Mac 开机联网、原隧道正常时，公网远窗仍可用。
- **Mac 自身关机或离线**：没有模型执行主机，公网也无法继续提供远窗服务；这与 DNS 回退不同。

Apple 官方机制：
https://developer.apple.com/documentation/devicemanagement/dnssettings/dnssettings-data.dictionary
https://github.com/apple/device-management/blob/release/mdm/profiles/com.apple.dnsSettings.managed.yaml

## 已部署

- 独立系统服务 `com.zhuangyi.remote-window.lan`，通过 launchd 套接字激活监听 443 和 8768，Python 以普通用户运行，不重启远窗主服务。
- 登录会话助手 `com.zhuangyi.remote-window.lan-cert`，每 6 小时经已有 SSH 同步原域名公开证书；失败时保留缓存，5 分钟后重试。
- 私钥保存到登录钥匙串 `remote-claude.lan-tls`，通过权限 0600 的用户 Unix socket 向网关提供，不放入仓库、参数或日志。OpenSSL 加载时只使用权限受限的临时文件并立即删除。
- 安装位置：`~/.local/share/remote-claude/lan/`。
- 日志：`~/Library/Logs/remote-claude/lan.log`、`lan-error.log`、`lan-cert.log`、`lan-cert-error.log`。不记录聊天内容、DNS查询明细、密码或证书私钥。
- 网关每 5 分钟刷新 TLS 上下文，不必重启已有会话。
- 标准 HTTPS、公开证书、专用加密 DNS、登录隔离、外站写入拦截及流式转发已自查；iPhone 已验证旧试用入口的登录与收发，新配置的实际回退仍需手机安装后验收。

## iPhone 最后一次设置

1. 当前 WiFi → 配置 DNS，保持“自动”。不要再手填 Mac IP。
2. 用 Safari 打开当前试用配置页 `http://192.168.31.208:8767/`，下载“远窗同网加速 · iOS 26+”。文件由用户已经信任的试用 HTTPS 入口提供。
3. 设置 → 通用 → VPN与设备管理，安装新描述文件。只含远窗专用 DNS 设置，不是根证书、VPN 或设备管理注册。
4. 完全关闭原桌面远窗后重开。使用相同网址和已有 Cookie，不需要新的桌面图标。
5. 验收通过后，可移除旧的“远窗局域网 HTTPS 试用”根证书描述文件；正式服务使用公开证书，不依赖旧根证书。

若手机已有 VPN、另一个 DNS 描述文件或代理，它们可能改变解析路径，需以实际连接为准。

## 验收

- 同 WiFi：原桌面远窗能正常查看、收发；Mac 443 有手机连接，才能算确认直连，而不是只看到页面可用。
- 手机切到蜂窝：原图标仍正常。
- 手机留在 WiFi、Mac 离家或局域网解析器不可达：短暂缓存等待后仍能通过公网访问；其它网站正常。Mac 仍需开机联网且原隧道正常。
- 回到同 WiFi：重新建立连接后能恢复直连。
- Mac 重启并登录后：运行 `verify.py` 检查服务、证书助手及自动恢复。

Mac 当前 LAN 地址为 `192.168.31.208`。地址变化会让该手机配置无法命中本地加速，系统应回退公网；恢复加速时需更新描述文件。可以在路由器保留此地址，但不再是保障手机正常上网的前提。

## Mac 自检

```sh
/Users/zhuangyi/Projects/04_项目/personal/remote-claude/.venv/bin/python /Users/zhuangyi/Projects/_scratch/小E/20261107-215/lan-final/verify.py
curl --noproxy '*' -sS -o /dev/null -w '%{http_code} %{remote_ip}\n' https://xiaoe.ericlab.cn/_x/health
```

第二条的对端应为 `127.0.0.1` 才证明 Mac 本机直连已生效。强制验证云端路径可使用 `curl --resolve xiaoe.ericlab.cn:443:47.107.105.209 https://xiaoe.ericlab.cn/_x/health`。

## 撤销

先在 iPhone 的 VPN与设备管理中移除“远窗同网加速”描述文件；WiFi DNS 维持自动。Mac 若配置了本机 hosts 映射，只移除 `# BEGIN remote-window local` 到 `# END remote-window local` 的块，保留其它行，刷新系统 DNS。

只有在 Mac hosts 映射已移除后，才停止独立网关：

```sh
sudo launchctl bootout system/com.zhuangyi.remote-window.lan
launchctl bootout gui/$(id -u)/com.zhuangyi.remote-window.lan-cert
sudo rm /Library/LaunchDaemons/com.zhuangyi.remote-window.lan.plist
rm ~/Library/LaunchAgents/com.zhuangyi.remote-window.lan-cert.plist
```

不操作远窗主服务与原隧道。原始 hosts 备份位于 `/etc/hosts.before-remote-window`；仅在确认没有之后的其它修改时才能整份恢复。证书缓存可在钥匙串访问中单独删除。
