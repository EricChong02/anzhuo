# 给 Codex 的话（复制下面整段发给 Codex，同时把《案头-设计方案.md》放进工作文件夹）

---

我想在自己的 Windows 电脑上做一个“远程工作台”：出门在外时，用鸿蒙手机打开一个网页（以后也可能用学校电脑），给家里这台 Windows 电脑上的你（Codex）派活。手机上能看到你在做什么、做完收到通知、能收到你交出来的文件。

工作文件夹里的《案头-设计方案.md》是朋友做好的同类系统，他已经用了一段时间。请把它当作主要参考：功能、流程、安全做法和“踩过的坑”尽量照搬。但我的情况和他不一样，下面这些以我说的为准：

1. **只用 Codex，不用 Claude。** 文档里 Claude 引擎、Claude Agent SDK、DeepSeek 翻译这些都不要。引擎只做 6.4 节的 Codex app-server（stdio JSON-RPC）。在开工前，先在我电脑上确认 `codex app-server` 能跑、协议和文档写的一致；不一致的以实测为准。
2. **电脑是 Windows，不是 Mac。**
   - 密钥放 Windows 凭据管理器（Python `keyring`），不放在配置文件或代码里。
   - 开机自启用“任务计划程序”的“用户登录时运行”，不要注册成系统服务，因为 Codex 的登录状态跟着我的账户走。
   - 文档里的 launchd、钥匙串、`/Applications/...` 路径都换成 Windows 的做法。要注意中文路径、GBK 编码和 PowerShell 执行策略。
   - 我双击用的 `.bat` 或 `.ps1` 脚本要中文显示正常，并写明每一步在做什么。
3. **手机是鸿蒙。** 不能假设网页推送（Web Push）一定能用。请先问我用哪个浏览器、平时用不用钉钉、企业微信或微信，再定通知方案；网页本身先保证能用。
4. **对外地址挂在朋友的阿里云服务器和域名下。** 他会给我：
   - 一个子域名（比如 `xxx.ericlab.cn`）；
   - 一个只能做端口转发的 SSH 账号；
   - 一个服务器端口号。
   我这边只需要用 Windows 自带的 OpenSSH 建一条反向隧道：`ssh -N -R 127.0.0.1:<端口>:127.0.0.1:<本机端口> <账号>@<服务器>`。断线要自动重连，开机自动起。nginx 和证书由他在服务器上配。你不要尝试登录或修改他的服务器，需要服务器那边做什么，写成一张清单让我转给他。
5. **安全不能比文档里弱：**
   - 网页登录要有密码和防暴力尝试；
   - 只认我自己一个人；
   - 删除、推送、改数据库这类危险命令要先确认（第 6.5 节）；
   - 日志里不记消息原文。
   这台电脑上有我的私人资料。

**做法：**

- **先问清需求，最多三轮。** 每轮最多 5 个问题，用选择题给出选项和你的推荐。至少问清：
  1. 平时想派哪几类活；
  2. 工作文件夹有哪些；
  3. 通知用什么；
  4. 要不要钉钉机器人入口（文档里有，可以不做，只用网页）；
  5. 危险命令是每次等我点确认，还是交给一个 AI 审核员判断（文档 6.5 节）；
  6. 要不要多个对话并行；
  7. 手机上要看到多少过程。
- **问完写一页计划给我看，我说可以再动手。** 计划要写明：分几步做、每一步做完我能看到什么、哪些事要我或朋友动手。
- **先做最小能用版：** 网页登录 → 派一句话给 Codex → 看到过程 → 收到结果 → 收到文件。先在本机浏览器跑通，再接隧道用手机试。之后再加通知、排队、插话、停止、额度显示这些。
- 每做完一步，都告诉我怎么亲手验证（打开哪个网址、点什么、应该看到什么）。我不看代码。
- 文档第 10 节“踩过的坑”在 Windows 上也大多适用，动手前先读一遍。
- 用中文和我交流。
