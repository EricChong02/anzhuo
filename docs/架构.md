# 架构

给想看懂代码、改代码、或者接入别的聊天软件的人。读完你应该知道：东西跑在哪、一句话进来怎么变成一次干活再变成一条通知、数据存在哪、哪些坑前人已经踩过。

## 几条设计取舍

1. **电脑不开放任何端口。** 网页只听 `127.0.0.1`；钉钉走官方 Stream 长连接；外网通路由你自己搭，并且是电脑主动连出去。
2. **登录、鉴权、业务全在电脑上。** 中转服务器（如果有）只转发加密流量，不存远窗的任何密钥或数据。
3. **对话内容存在 Claude Code / Codex 自己的目录里**（`~/.claude`、`~/.codex`）。远窗只记“编号 ↔ 会话 ID ↔ 文件夹”的对应，以及每轮的记录（给“完整过程”页和 GPT 对话的历史用）。所以桌面端、命令行、手机三边能接着聊同一个对话。
4. **前端是一页原生 HTML/JS，没有构建步骤**：骨架在 `static/app.html`，样式和脚本按主题分在 `static/app/`，每次请求由 `webui.py` 按固定顺序拼回一页（脚本拼进同一个 `<script>`，共用作用域）。只改界面不用重启进程，刷新即生效。
5. **单进程、asyncio。** 一台电脑、一个用户，不需要更复杂的东西。并行靠“每个对话一个工作协程 + 信号量”（`max_parallel`）。
6. **入口是可插拔的**：Bridge 对“怎么把消息发给用户”的依赖只有 `dingtalk.py` 里 `DingTalk` 的十来个异步方法；没开钉钉时换成同接口的 `NoDingTalk`（什么都不做）。要加 Telegram / 飞书 / 企业微信，照 `NoDingTalk` 的接口实现一个，再在 `anzhuo/__init__.py` 的 `run()` 里按配置选用即可。

## 一句话进来之后发生了什么

以网页上发一句话为例（钉钉的路径相同，只是入口换成 `Bridge.on_raw`）：

1. 浏览器 `POST /_x/api/send`（`web/actions.py: _api_send`）。校验登录和同源；如果是定时任务的说法（“每天 8 点……”）就走 `schedules.parse_request`，否则继续；
2. 带 `num` → 交给已有对话（`Bridge.message` → `submit`）；不带 → 新开（`Bridge.new_session` → `start_session`，解析文件夹、挑模型、建 `Session`）；
3. `Runner.submit` 把这件事放进该对话的队列：对话正在做事 → 直接**插话**（Claude 用流式输入，Codex 用 `turn/steer`）；否则排队，等信号量有空位；
4. 工作协程 `Runner._run` 把这一轮交给对话的引擎（`engines/`：Claude 起 `ClaudeSDKClient`，GPT 起 Codex 连接，Kimi 等走 ACP），把你的话（连同图片）送进去，开始**逐条读事件**：说了什么、调用了哪个工具、思考摘要……每个事件更新这一轮的 `Turn`（步骤、时间线、改的文件、跑的命令、计划清单）；网页的 SSE 把变化推给浏览器；
5. 要跑命令、删 / 挪文件 → 统一走 `engines/policy.py`（取出命令或路径 → `guard.danger()` 判）；命中就 `Runner.decide`：开了审核员就交 `reviewer.review`，否则 `ask_confirm`（网页卡片 + 手机通知 + 钉钉按钮卡），最长等 20 分钟；
6. 这一轮结束 → `Bridge._turn_done`：必要时翻译英文、`report.build` 排报告、`web.save_turn` 把这一轮写进 `turns/`、更新“是不是在等你”（`asks_user` / `awaiting_kind`）、按**通知策略**发（你正在看 → 不发；没在看 → Web Push；一台都没发到且开了钉钉 → 钉钉一句话）；
7. 浏览器收到 SSE 通知，刷新列表和对话。

## 模块一览

| 模块 | 行数 | 做什么 |
|---|---:|---|
| `app.py` | ~1000 | `Bridge`：把网页和钉钉两个入口接到同一套对话上；新开 / 交给谁 / 定时派发 / 通知策略 / 额度自动续；常驻主循环 |
| `sessions.py` | ~580 | 对话登记表 `Registry`、调度的 `Runner`（排队、并行名额、插话与停下的分派、`Turn` 的构造与收尾、危险操作的 `decide`） |
| `engines/` | ~1200 | 引擎（Strategy）：`base.py` 接口与能力声明；`claude.py` / `codex.py` / `acp.py` 三种跑法（钩子、MCP 工具、事件翻译）；`catalog.py` 引擎目录、型号表 `MODELS`、选模型的键 → 引擎；`policy.py` 统一的工具批准 |
| `web/` | ~2400 | aiohttp 网页服务。`core.py` 只管状态、鉴权、路由表、SSE、启动；接口按主题分在 `auth`（登录设备）、`listing`（对话列表、选文件夹、定时）、`threads`（对话记录、搜索、翻译）、`actions`（发话和操作）、`rewind`（回退分叉）、`turns`（过程页、文件）、`audio`（朗读）、`admin`（管理、设置） |
| `static/app.html` + `static/app/` | ~3000 | 前端：骨架一个 HTML，样式 3 个、脚本 14 个按主题分（列表、对话、输入框、额度、管理……），顺序见 `webui.APP_JS` |
| `codex.py` | ~210 | Codex 的常驻连接（`codex app-server`，stdio 上一行一条 JSON-RPC）：开 / 接着会话、开一轮、插话、停止、压缩、额度、审批 |
| `checkpoints.py` | ~180 | Codex 每轮前后的工作文件快照，回退时只恢复该轮差异，先查冲突，保留撤销副本 |
| `schedules.py` | ~220 | 定时任务：中文时间解析、持久化、错过的补做、先记凭据再提交以防重复 |
| `thread.py` | ~200 | 读 Claude 的会话记录，整理成“你说的 / 它答的 / 工作过程”；压缩过的接回压缩前的部分 |
| `report.py` | ~220 | `Turn` 数据结构；把一轮的结果排成报告、手机通知的一句话 |
| `reviewer.py` | ~90 | 可选的 AI 审核员 |
| `guard.py` | ~50 | 危险命令的识别规则（删文件按 `rm <路径>` 同一套判，见 `engines/policy.py`） |
| `dingtalk.py` | ~220 | 钉钉收发（可选）+ `NoDingTalk` 空实现 |
| `cards.py` | ~180 | 钉钉卡片：工作台、“要你定”按钮、确认卡；也负责把“要你定：A. B. C.”解析成选项（网页按钮也用它） |
| `commands.py` | ~85 | 钉钉里的一句话 → 指令 |
| `folders.py` | ~110 | 文件夹解析：短名、路径、按名字找、临时文件夹；对受保护文件夹用可杀掉的子进程探测，防卡死 |
| `push.py` | ~100 | Web Push：VAPID 密钥、订阅、发送、同步订阅到看守服务器 |

| `cleanup.py` | ~120 | 可选整理（`auto_cleanup`）：归档旧对话记录、清旧临时文件夹、每月体检 |

| `__init__.py` | ~160 | 命令行：`run` / `check` / `passwd` / `whoami` |

## 关键数据结构

- **`Session`**（`sessions.py`）：一个对话。`num` 是你看到的编号，`claude_id` / `codex_id` 是引擎那边的会话 ID，`cwd` 是工作文件夹，另有名字、模型、深度、状态、`awaiting`（在等你回答什么）、`limit_until`（撞额度后几点恢复）、回退 / 分叉的标记……`Registry` 把它们存成 `sessions.json`，读取时忽略不认识的字段，所以版本升级不会读不开旧数据。
- **`Turn`**（`report.py`）：一轮工作。步骤、时间线（说了什么 / 做了什么，过程页用）、改的文件、跑的命令、交出的图和文件、最终回复、计划清单、派出的助手、等你确认的危险操作……是运行中的“实时状态”，做完后落成 `turns/<编号>-<n>.json`。
- **`Incoming`**（`dingtalk.py`）：统一的“收到的一句话”，网页和钉钉都构造它，`via` 记来源（`web` / `dingtalk` / `schedule` / `auto`）；通知策略据此决定“结果发到哪”。

## 并发与状态

- 一个进程、一个事件循环。`Runner` 给每个对话一个队列和一个工作协程，`asyncio.Semaphore(max_parallel)` 限同时干活的数量。
- 状态都在内存里，**周期性写盘**（`sessions.json` 等）；重启时把写着“在做 / 排队”的对话标成出错（因为进程没了），额度恢复的自动续也在重启后重新挂上。
- `Web.watch` 记“你正开着看哪个对话”（网页每 15 秒报一次），通知策略靠它判断要不要打扰。

## 测试

```bash
.venv/bin/pytest -q
```

全部离线，不连 Claude、钉钉或钥匙串。几种写法：

- **`FakeDT`（假钉钉）+ 替换 `Runner._run`（假 AI，跳过引擎）+ 真 `Bridge`**：走完整的“收到消息 → 新开 → 干活 → 通知”流程（`tests/test_bridge.py`），这是最能抓“端到端串起来后才出的错”的一类测试；
- **aiohttp 的 `TestClient` 打真的网页服务**（`tests/test_web.py`）：登录、接口、同源校验、文件收发、回退分叉；
- **`tests/test_open_source.py`**：开源底线——没钉钉也能跑、默认配置保守、内置提示词不含个人授权、仓库里没有个人信息。

另有 **`scripts/demo.py`** 演示模式：用同样的假 AI 起一个只有虚构对话的网页，用来看界面和截图。

## 踩过的坑（改相关代码前先看）

| 坑 | 现象 | 解决 |
|---|---|---|
| SDK 默认 1MB 读缓冲 | Claude 看一张大截图，整轮报错 | `max_buffer_size=64MB` |
| Codex 子进程的 stderr 没人读 | 跑一会儿就卡死 | 单独开协程一直读 |
| Codex 审批请求在读取循环里 `await` | 等你确认时所有事件都停了 | 每个反向请求 `create_task` 单独处理 |
| SDK 只读压缩点之后的记录 | 压缩过的对话，网页上早先的内容全没了 | 顺着 `logicalParentUuid` 把前段接回（`thread.full_messages`） |
| 中途插的话在记录里是 attachment | 网页上插的话一直显示“发送中” | 解析 `queued_command` 附件 |
| 压缩时插话 | 你的话被压缩吞掉 | 压缩那一轮不插话，改为排队 |
| 新开对话时局部变量覆盖了你选的模型 | 选了 GPT 却跑成 Opus | 用真 Bridge + 假钉钉写端到端测试 |
| 前端热更新快于后端 | 新界面配旧后端，缺字段时默认值导致误标 | 字段缺失就不显示，不要猜默认值 |
| CSS 盖掉了 `hidden` 属性 | 按钮藏不掉，像卡住 | 全局 `[hidden]{display:none!important}` |
| iPhone 冷启动点通知 | 打开的是首页，不是对应对话 | Service Worker 先把编号写进 Cache，页面启动时读 |
| PWA 里打开图片没有返回键 | 被困在图片页 | 自己做图片查看器，不跳转 |
| SSE 被 nginx 缓冲或超时 | 实时更新一卡一卡，或断开 | `proxy_buffering off` + 每 15 秒发一个空行保活 |
| 翻译完成时整块重绘 | 正在看的“工作过程”被刷新、滚动位置丢了 | 翻译中显示占位；选中文字时不重绘；记住展开和滚动状态 |
| 在远窗里直接重启远窗 | 自己被打断，别的对话也断了 | `scripts/restart_when_idle.py` 等所有对话空闲再重启；`launchctl kickstart -k` 列为危险命令 |
| Codex 只写 Markdown 下载链接 | 手机上点不开，文件没交出来 | 解析链接；约定里要求用“交给你：路径”的写法 |
| 后台进程访问“下载”等受保护文件夹 | 系统授权弹窗没人点，永远卡住 | 先用可杀掉的子进程探测 5 秒，读不了就报错并说明怎么授权 |
| 钉钉“吊顶卡片” | 机器人单聊里用不了（只支持企业群） | 改用每次都重发到底部的“工作台”卡 |

## 已知局限

- 平台：macOS 是开发验证平台（`security` 钥匙串、`launchctl`、`caffeinate`、`/bin/ls` 探测目录）。本仓库已带 Windows 适配：密钥存储分平台（`write_web_hash` / `read_web_hash`，非 macOS 落 `web_hash.json`）、CLI 路径按平台补 `.exe`、`folders.readable` 非 macOS 直接 `is_dir()`、`LINK` / `candidates` 认盘符路径、`tzdata` 依赖 + `anzhuo.cmd` 强制 UTF-8。钉钉密钥、推送 VAPID 私钥仍只写 macOS 钥匙串；Linux 未验证，欢迎贡献。
- Codex 引擎依赖 ChatGPT 桌面版自带的 `codex` 可执行文件（固定路径 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`），协议随它升级可能变。
- 界面和提示词是中文；英文化需要改 `app.html`、`report.py`、`commands.py` 和给对话追加的约定。
- 危险命令识别只覆盖 Bash 命令、基于正则，见 [安全说明](安全说明.md)。
